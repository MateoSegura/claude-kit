# Report Formats — Templates and Schemas

Complete output templates for the `report-generator` agent. Three report types: Markdown Grade Report, JSON Scorecard, and Comparative Report (compare mode).

---

## 1. Markdown Grade Report Template

File naming convention: `{project-name}-grade-report.md`

```markdown
# Svelte/SvelteKit — Code Quality Report

| | |
|---|---|
| **Project** | {project_name} |
| **Date** | {graded_at} |
| **Branch** | `{git_branch}` |
| **Commit** | `{git_commit_short}` |
| **Working Tree** | {git_clean_or_dirty} |

---

## Executive Summary

**Overall Score: {composite_score}/100 — Grade {letter_grade} — {PASS|FAIL}**

{2-3 sentence overview. State the strongest dimension, the weakest dimension, and the most critical finding. Example: "This submission demonstrates strong TypeScript discipline (92/100) and good component composition patterns. The primary concern is accessibility (48/100): three interactive elements are not keyboard-reachable, which constitutes a WCAG 2.1.1 failure and forces an overall FAIL. Testing quality also needs improvement — no tests exist for the data-fetching layer."}

{If overall_critical_failure is true, include this block:}
> **CRITICAL FAILURE:** This submission fails due to: {override_reason}. This overrides the composite score of {composite_score}.

---

## Dimension Scorecard

| Dimension | Score | Grade | Weight | Pass? | Confidence |
|-----------|-------|-------|--------|-------|------------|
| Component Quality | {score}/100 | {grade} | {weight}% | {✓|✗} | {high|medium|low} |
| State Management | {score}/100 | {grade} | {weight}% | {✓|✗} | {high|medium|low} |
| Styling/CSS | {score}/100 | {grade} | {weight}% | {✓|✗} | {high|medium|low} |
| Accessibility | {score}/100 | {grade} | {weight}% | {✓|✗} | {high|medium|low} |
| Performance | {score}/100 | {grade} | {weight}% | {✓|✗} | {high|medium|low} |
| TypeScript Usage | {score}/100 | {grade} | {weight}% | {✓|✗} | {high|medium|low} |
| Testing Quality | {score}/100 | {grade} | {weight}% | {✓|✗} | {high|medium|low} |
| UX Patterns | {score}/100 | {grade} | {weight}% | {✓|✗} | {high|medium|low} |
| **Composite** | **{composite}/100** | **{grade}** | — | **{PASS\|FAIL}** | **{conf}** |

{If N/A dimensions exist:}
> **N/A Dimensions:** {dim_name} — {na_reason}. Weight redistributed proportionally to active dimensions.

---

## Critical & Major Findings

{List all critical and major findings across all dimensions, grouped by severity then dimension.}

### Critical Findings

{For each critical finding:}

#### [{id}] {title}

- **Dimension:** {dimension}
- **File:** `{file}:{line}`
- **Evidence:** {evidence}
- **Fix:**

```{lang}
{fix_code_example}
```

---

### Major Findings

{For each major finding — same format as critical, without horizontal rule between them.}

---

## Dimension Details

{One section per evaluated dimension, in order.}

### 1. Component Quality — {score}/100 ({grade})

**Summary:** {1-2 sentence summary of this dimension's evaluation.}

**Findings:**

| ID | Severity | File | Title |
|----|----------|------|-------|
| {id} | {severity} | `{file}` | {title} |

{For each finding, a detail block:}

**{id}: {title}**
- Severity: {severity}
- File: `{file}:{line}`
- Evidence: {evidence}
- Fix: {fix_suggestion}

**What was done well:**
{positive_notes as bullet list}

{Repeat for all 8 dimensions}

---

## Fix Priority List

Fix these issues in priority order to improve the grade:

1. **[CRITICAL] {title}** ({dimension}) — {brief fix description}
2. **[CRITICAL] {title}** ({dimension}) — {brief fix description}
3. **[MAJOR] {title}** ({dimension}) — {brief fix description}
{...continue for all critical and major findings}

---

## What Was Done Well

{Bullet list of positive notes from all dimensions. Include the dimension name in parentheses.}

- {positive note} ({dimension})
- {positive note} ({dimension})

---

*Report generated by coding-frontend-svelte-grader. This report evaluates code quality only and does not modify any source files.*
```

```

### Required JSON Fields

The `validate-report-json.sh` hook validates these required fields:

| Field Path | Type | Required |
|------------|------|----------|
| `version` | string | Yes |
| `project` | string | Yes |
| `graded_at` | ISO 8601 string | Yes |
| `result.composite_score` | number (0-100) | Yes |
| `result.letter_grade` | "A"\|"B"\|"C"\|"D"\|"F" | Yes |
| `result.pass` | boolean | Yes |
| `result.critical_failure` | boolean | Yes |
| `dimensions` | array (length 8) | Yes |
| `dimensions[].id` | string | Yes |
| `dimensions[].score` | number or null | Yes |
| `dimensions[].pass` | boolean | Yes |
| `dimensions[].findings` | array | Yes |
| `dimensions[].findings[].severity` | "critical"\|"major"\|"minor"\|"info" | Yes |
| `dimensions[].findings[].fix_suggestion` | string | Yes (critical/major) |

## 3. Comparative Report Template (compare mode)

File naming convention: `comparison-{project-a}-vs-{project-b}-report.md`

```markdown
# Comparative Grade Report: {Project A} vs {Project B}

**Graded:** {graded_at}
**Mode:** A/B Comparison

---

## Comparison Summary

| | {Project A} | {Project B} | Delta |
|---|---|---|---|
| **Composite Score** | {score_a}/100 ({grade_a}) | {score_b}/100 ({grade_b}) | {delta:+.1f} |
| **Overall Result** | {PASS\|FAIL} | {PASS\|FAIL} | — |
| **Critical Failures** | {count_a} | {count_b} | — |
| **Major Findings** | {count_a} | {count_b} | {delta} |

{If delta > 0: "{Project B} scores {delta} points higher overall."}
{If delta < 0: "{Project A} scores {abs(delta)} points higher overall."}
{If delta == 0: "Both projects achieve the same composite score."}

---

## Dimension-by-Dimension Comparison

| Dimension | {Project A} | {Project B} | Delta | Better |
|-----------|-------------|-------------|-------|--------|
| Component Quality | {score_a} | {score_b} | {delta:+d} | {A\|B\|Tied} |
| State Management | {score_a} | {score_b} | {delta:+d} | {A\|B\|Tied} |
| Styling/CSS | {score_a} | {score_b} | {delta:+d} | {A\|B\|Tied} |
| Accessibility | {score_a} | {score_b} | {delta:+d} | {A\|B\|Tied} |
| Performance | {score_a} | {score_b} | {delta:+d} | {A\|B\|Tied} |
| TypeScript Usage | {score_a} | {score_b} | {delta:+d} | {A\|B\|Tied} |
| Testing Quality | {score_a} | {score_b} | {delta:+d} | {A\|B\|Tied} |
| UX Patterns | {score_a} | {score_b} | {delta:+d} | {A\|B\|Tied} |

---

## Regressions

{List dimensions where Project B scores lower than Project A by > 5 points.}
{If none: "No significant regressions detected."}

- **{dimension}:** {project_a} scored {score_a} vs {project_b} scored {score_b} (−{abs(delta)} points). Likely cause: {inferred from findings}

---

## Improvements

{List dimensions where Project B scores higher than Project A by > 5 points.}
{If none: "No significant improvements detected."}

- **{dimension}:** {project_a} scored {score_a} vs {project_b} scored {score_b} (+{delta} points). Attributed to: {inferred from findings}

---

## Unique Findings by Project

### Found in {Project A} only

{Findings present in Project A that are not present in Project B, organized by dimension.}

### Found in {Project B} only

{Findings present in Project B that are not present in Project A.}

### Found in Both

{Findings present in both projects — shared technical debt.}

---

## Individual Reports

Full per-dimension findings are in the individual grade reports:

- [{Project A} Grade Report]({project_a}-grade-report.md)
- [{Project B} Grade Report]({project_b}-grade-report.md)

---

*Comparative report generated by coding-frontend-svelte-grader. Neither codebase was modified during evaluation.*
```

## Report File Placement

The report-generator writes reports to a timestamped `reports/` subdirectory at the project root, then zips everything for easy transfer. Default paths:

| Report Type | Default Path |
|-------------|-------------|
| Markdown Grade Report | `./reports/<YYYY-MM-DD_HH-MM-SS>/{project-name}-grade-report.md` |
| JSON Scorecard | `./reports/<YYYY-MM-DD_HH-MM-SS>/{project-name}-scorecard.json` |
| Comparative Report (MD) | `./reports/<YYYY-MM-DD_HH-MM-SS>/comparison-{a}-vs-{b}-report.md` |
| Comparative JSON | `./reports/<YYYY-MM-DD_HH-MM-SS>/comparison-{a}-vs-{b}-scorecard.json` |
| Zip Archive | `./reports/<YYYY-MM-DD_HH-MM-SS>/contents.zip` |

Attempting to write to source files (`.svelte`, `.ts`, `.js`, `.css`) is blocked.
