# Coverage Analysis Reference

## Interpreting Uncovered Branches

### Example: Uncovered Branch in Utility Function

Source:
```typescript
// src/lib/utils/validate.ts (line 28-35 uncovered)
export function validateEmail(email: string): ValidationResult {
  if (!email) {                          // line 28 — branch: empty string
    return { valid: false, error: 'Email is required' };   // line 29 — never hit
  }
  if (!email.includes('@')) {            // line 31
    return { valid: false, error: 'Invalid email format' }; // line 32 — never hit
  }
  return { valid: true };
}
```

Coverage report shows: `| 72.7 | 62.5 | 83.3 | 73.3 | 28-35`

**Diagnosis:** The error branches (lines 28-35) are never reached because no test passes an empty string or a string without `@`.

**Fix:**
```typescript
it.each([
  ['', 'Email is required'],
  ['notanemail', 'Invalid email format'],
  ['also-not@valid', undefined],  // wait, no — needs @
])('validates %s', (input, expectedError) => {
  const result = validateEmail(input);
  if (expectedError) {
    expect(result.valid).toBe(false);
    expect(result.error).toBe(expectedError);
  } else {
    expect(result.valid).toBe(true);
  }
});
```

### Ternary Operators — Two Branches Each

```typescript
// This line creates TWO branches:
const display = count === 0 ? 'No items' : `${count} items`;
//              ↑ false branch covered?   ↑ true branch covered?
```

Coverage tools will show branch 50% if all tests pass `count = 5` but never `count = 0`.

### Optional Chaining — Branch for null/undefined

```typescript
const name = user?.profile?.displayName ?? 'Anonymous';
// 4 branches: user null, user.profile null, displayName null, all defined
```

### Short-Circuit Evaluation

```typescript
const label = isLoading && 'Loading...';
// Branch: isLoading=true (truthy) and isLoading=false (falsy)
```

## Coverage Gap Prioritization Heuristics

When coverage is below 80%, use this priority order to decide what to test next:

### Priority 1: Critical User Paths
Functions called in the main happy path of the application. If these are untested and fail, users cannot accomplish their primary goals.

```bash
# Find uncovered files in critical paths
grep -r "export" src/lib/auth/ src/lib/payment/ src/routes/checkout/
# Cross-reference with coverage JSON
```

### Priority 2: Error Handling Paths
Error branches that, if incorrect, cause crashes or data loss rather than degraded experience.

```typescript
// These uncovered error paths are HIGH priority:
catch (error) {
  // line 45 — never hit in tests
  if (error instanceof NetworkError) {
    showOfflineMessage();
  }
}
```

### Priority 3: Business Logic Branches
Conditional logic that determines application behavior (pricing tiers, permission checks, feature flags).

### Priority 4: Edge Cases
Null/undefined guards, empty arrays, boundary values. Important but lower impact than business logic.

### Priority 5: Type Guards and Assertions
Runtime type checks. Usually low risk unless they silently fail.

```typescript
// Low priority to test — pure runtime safety net
function assertNever(x: never): never {
  throw new Error(`Unexpected value: ${x}`);
}
```

## Excluding Generated Code and Type Guards from Coverage

### Excluding Files

```typescript
// vitest.config.ts
coverage: {
  exclude: [
    // Generated by SvelteKit
    '.svelte-kit/**',
    'src/**/$types.ts',

    // Type-only files
    'src/app.d.ts',
    'src/**/*.d.ts',

    // Barrel exports (just re-exporting, no logic)
    'src/lib/index.ts',
    'src/**/index.ts',

    // Storybook files
    'src/**/*.stories.ts',
    'src/**/*.stories.svelte',

    // Config files
    'src/lib/config/*.ts',  // if they contain only constants
  ],
}
```

### Inline Ignores

For specific lines/blocks that should not affect coverage metrics:

```typescript
// v8 provider syntax
/* v8 ignore next -- @preserve */
console.debug('Development only:', value);  // line ignored

/* v8 ignore if -- @preserve */
if (process.env.NODE_ENV === 'development') {
  // this block ignored in coverage
}

// istanbul provider syntax (also works in v8)
/* istanbul ignore next */
function assertNever(x: never): never {
  throw new Error(`Unexpected: ${x}`);
}
```

## JSON Summary Format

The `json-summary` reporter produces a file at `coverage/coverage-summary.json`:

```json
{
  "total": {
    "lines": { "total": 450, "covered": 382, "skipped": 0, "pct": 84.89 },
    "statements": { "total": 523, "covered": 447, "skipped": 0, "pct": 85.47 },
    "functions": { "total": 87, "covered": 74, "skipped": 0, "pct": 85.06 },
    "branches": { "total": 134, "covered": 108, "skipped": 0, "pct": 80.60 }
  },
  "src/lib/utils/format.ts": {
    "lines": { "total": 28, "covered": 28, "skipped": 0, "pct": 100 },
    "functions": { "total": 6, "covered": 6, "skipped": 0, "pct": 100 },
    "statements": { "total": 32, "covered": 32, "skipped": 0, "pct": 100 },
    "branches": { "total": 10, "covered": 8, "skipped": 0, "pct": 80 }
  },
  "src/lib/utils/validate.ts": {
    "lines": { "total": 45, "covered": 33, "skipped": 0, "pct": 73.33 },
    "functions": { "total": 6, "covered": 5, "skipped": 0, "pct": 83.33 },
    "statements": { "total": 55, "covered": 40, "skipped": 0, "pct": 72.73 },
    "branches": { "total": 16, "covered": 10, "skipped": 0, "pct": 62.5 }
  }
}
```

**Parsing files below threshold:**
```bash
# Files with branch coverage below 80%
cat coverage/coverage-summary.json | \
  jq '[to_entries[] | select(.key != "total") | select(.value.branches.pct < 80)] | \
  sort_by(.value.branches.pct) | \
  map({file: .key, branches: .value.branches.pct})'
```

## CI Integration

### GitHub Actions — Fail on Threshold Miss

Vitest exits with code 1 when thresholds are not met. No extra CI config needed:

```yaml
- name: Run tests with coverage
  run: npx vitest run --coverage
  # Exits 1 if any threshold is missed
```

### Coverage Badge (shields.io)

```bash
# Extract total line coverage percentage
COVERAGE=$(cat coverage/coverage-summary.json | jq '.total.lines.pct')
echo "Coverage: ${COVERAGE}%"

# Generate badge URL
BADGE_URL="https://img.shields.io/badge/coverage-${COVERAGE}%25-brightgreen"
```

### PR Coverage Comment (GitHub Actions)

```yaml
- name: Coverage summary
  run: |
    LINES=$(cat coverage/coverage-summary.json | jq '.total.lines.pct')
    BRANCHES=$(cat coverage/coverage-summary.json | jq '.total.branches.pct')
    echo "## Coverage Report" >> $GITHUB_STEP_SUMMARY
    echo "| Metric | Coverage |" >> $GITHUB_STEP_SUMMARY
    echo "|--------|----------|" >> $GITHUB_STEP_SUMMARY
    echo "| Lines | ${LINES}% |" >> $GITHUB_STEP_SUMMARY
    echo "| Branches | ${BRANCHES}% |" >> $GITHUB_STEP_SUMMARY
```

## v8 vs Istanbul: When to Switch

| Scenario | Use v8 | Use istanbul |
|----------|--------|-------------|
| Standard TypeScript/Svelte project | Yes | |
| Running on Bun runtime | | Yes |
| Need Firefox browser tests | | Yes |
| Cloudflare Workers | | Yes |
| Complex source maps | | Yes (more accurate) |
| Maximum speed | Yes | |
| Maximum compatibility | | Yes |

Switch provider: `coverage: { provider: 'istanbul' }` — no other changes needed.
