# NIST SP 800-218 -- Secure Software Development Framework (SSDF) v1.1

## Mapping to claude-kit Base Layer Processes

**Version:** 1.0.0
**Status:** draft
**Last Reviewed:** 2026-02-28

## Overview

NIST Special Publication 800-218 defines the Secure Software Development
Framework (SSDF), a set of fundamental secure software development practices
organized into four groups. This document maps all 24 base layer processes in
the claude-kit QMS to the SSDF practices they support.

The SSDF is structured as:
- **PO -- Prepare the Organization:** Organizational preparation for secure development
- **PS -- Protect the Software:** Protecting all components of the software from tampering and unauthorized access
- **PW -- Produce Well-Secured Software:** Producing well-secured software with minimal vulnerabilities
- **RV -- Respond to Vulnerabilities:** Identifying residual vulnerabilities and responding appropriately

### Gap Analysis

All 34 SSDF sub-practices are covered by at least one claude-kit process.
Ten sub-practices have partial coverage, meaning the process addresses the
intent but does not yet implement every recommended activity. These partial
coverages are concentrated in:

- **PO.1 (Security Requirements):** Market analysis and risk management
  contribute to but do not solely satisfy security requirements definition.
  Full satisfaction requires PROC-LC-002 (Requirements Engineering) to explicitly
  tag security-relevant requirements.

- **PO.2 (Roles and Responsibilities):** Training and access control address
  role definition partially. A dedicated security role definition (Security Lead
  in process documents) strengthens this but is not yet formalized in an
  organizational chart.

- **PO.3 (Toolchains):** Tool evaluation and evidence production are partially
  covered through continuous improvement and configuration management. Full
  coverage would require a dedicated tool qualification process.

- **PW (Produce Well-Secured Software):** Implementation, review, and build
  configuration have partial coverage where claude-kit's unique architecture
  (single-file CLI, interpreted Python) limits the applicability of traditional
  compiler-level security controls.

### Recommendations for Improving Coverage

1. **Formalize security requirement tagging:** In PROC-LC-002, add a mandatory
   security tag to REQ-XXX documents that carry security implications.

2. **Create an organizational role chart:** Document security roles formally
   rather than relying solely on process role tables.

3. **Automate SBOM generation:** Add a CI step to PROC-SEC-002 that generates
   the SBOM automatically on each release.

4. **Add static analysis tooling:** Integrate bandit or equivalent Python
   security linter into the CI pipeline to strengthen PW.5 and PW.7 coverage.
